# Provider terms check

Checked on **2026-10-07** for phase 1 of the Claude Indicator beta. This is an engineering assessment of the published terms and the implemented data sources, not legal advice or a provider's approval. A free public download and a later paid desktop tool are assessed separately from reselling provider access: every user must use their own authorized account, credentials, and local data. Charging for the Indicator does not itself grant permission to access a provider's private endpoints.

## Scope and evidence

The implementation inspected is `d857694a050ddfb8774ce99be64e774ded5d9426`, principally `claude_widget.py`, `scripts/ollama_watchdog.py`, and the local TODO/recovery modules. Function names below locate the relevant behavior even when later commits move line numbers. This check read source and fetched public legal/documentation pages only; it did **not** authenticate to any usage endpoint, make an inference request, refresh credentials, or test accounts. Historical comments and successful responses reported in project notes are not provider authorization. “Documented” below means that the public provider documentation explicitly describes that interface; an official-looking hostname, a working request, or a third-party tracker is insufficient.

Task 8 adds the Cursor adapter in `cursor_usage.py`, checked against current official documentation and terms on the same date. Its tests use only mocks; the owner source check found no configured eligible key and no stored usage snapshot. The disconnected state makes no Cursor request.

Verdicts use **allowed** for a supported source used within the stated conditions, **grey area** for a material unresolved permission or contract question, and **likely prohibited** for an implemented access method that appears inconsistent with an express restriction and has no documented exception. They concern the current adapter, not every possible integration with that provider.

## Relevant clauses and primary sources

All sources below were retrieved for this check on 2026-10-07. Dates are the pages' displayed effective/update dates, not inferred from search-result crawl dates. Legal texts are paraphrased except for the short quotations marked below; no single source is quoted beyond 25 words.

- **Anthropic:** [Consumer Terms](https://www.anthropic.com/legal/consumer-terms), effective October 8, 2025, section 3(7), restrict automated access except via an Anthropic API key or explicit permission: “to access the Services through automated or non-human means”. Section 3(4) also restricts harvesting service data; section 2 restricts credential/account sharing. [Usage Policy](https://www.anthropic.com/legal/aup), effective September 15, 2025, prohibits abuse and unauthorized account/API access and does not supply an exception for an external subscription meter. [Official authentication guidance](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account), with no absolute effective date shown, tells developers building tools for others: “use API key authentication through Claude Console or a supported cloud provider”. It prohibits misrepresenting application identity and routing third-party traffic against subscription limits; limited discretionary access through usage credits is not blanket permission. This supports the current-adapter verdict rather than a claim that passive local status-line data is prohibited.
- **Claude safer interfaces:** [Status-line documentation](https://code.claude.com/docs/en/statusline#available-data) explicitly supplies `rate_limits.five_hour`, `rate_limits.seven_day`, percentages, and reset timestamps. It describes local execution without API-token consumption. Preserve freshness and missing-field handling; it is not a continuously refreshed external API. [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api) documents organization usage/cost reporting and special admin/analytics credentials; personal subscription quotas and Claude Platform billing must not be conflated. Documentation pages did not show an absolute effective date.
- **OpenAI:** [Terms of Use](https://openai.com/policies/terms-of-use/), effective January 1, 2026, restrict “Automatically or programmatically extract data or Output” and rate-limit circumvention. [Services Agreement](https://openai.com/policies/services-agreement/), updated December 1, 2025/effective January 1, 2026, section 3.3(f), restricts extracting data “other than as permitted through the Services”; section 2.2 permits API integration into customer applications, and section 3.1 forbids account-access resale. The account's applicable agreement depends on plan/customer type; being a developer does not automatically move personal ChatGPT usage onto business terms. [Official Codex app-server documentation](https://learn.chatgpt.com/docs/app-server) explicitly documents `account/rateLimits/read` for ChatGPT limits and third-party clients, which is the supporting permission evidence for the implemented route. [Usage Policies](https://openai.com/policies/usage-policies/), effective October 29, 2025, forbid privacy violations and safeguard circumvention. [Codex license](https://github.com/openai/codex/blob/main/LICENSE) is Apache-2.0; an open-source code license does not override service-account terms.
- **Cursor / Grok Bot:** [API overview](https://cursor.com/docs/api) explicitly lists Enterprise teams for Admin API availability and custom dashboards/monitoring as a supported purpose; Admin keys use `crsr_` and `admin:*`, with Basic authentication. [Admin spending schema](https://cursor.com/docs/account/teams/admin-api) distinguishes on-demand `spendCents` from total `overallSpendCents` and exposes cycle start, not plan quota/reset. [Terms](https://cursor.com/terms-of-service), last updated September 3, 2026, section 1.5 restricts “harvest, scrape, or extract data” and selling the Service. The documented API supports this conditional own-account monitoring inference; it does not authorize private session-token endpoints or resale of provider access. [Grok Bot plans](https://cursor.com/help/grok-bot/plans) place Bot billing on Cursor, separate from SuperGrok. [CLI release notes](https://cursor.com/docs/release-notes) describe `/usage` with plan/reset information; that does not document a disk cache or authorize private HTTP extraction. Static inspection identified only in-memory usage caching in the installed Bot display, so no such local adapter is shipped.
- **DeepSeek:** [API reference](https://api-docs.deepseek.com/api/get-user-balance/) explicitly documents `GET /user/balance` and its balance fields; public HTTP retrieval succeeded even though the research browser's fetch timed out. [Terms of Use](https://cdn.deepseek.com/policies/en-US/deepseek-terms-of-use.html), last updated March 27, 2026, section 3.6(4), restricts “selling, or sub-licensing the entire or part of the Services” without authorization. Sections 3.3–3.5 cover usage restrictions, network abuse, unauthorized access, and copying/extraction. Reading one's balance through its published API is materially different from scraping the web service or reselling access; this is the basis for the conditional allowed verdict. The terms also require lawful, accurate handling of generated content; this adapter generates none.

## Phase 1 consequence and owner decisions

This check is complete as a documented review; it is **not** provider approval or clearance for launch. The existing Claude, Go, and Grok live adapters should not be described as official, provider-approved, or cleared for sale. Prefer supported local/provider interfaces above and seek written clarification where needed before relying on those adapters in a distributed or paid product. MiniMax's published endpoint offers a concrete safer route, with a remaining commercial-language question. No permission request, account action, paid test, or message to a provider was made during this check.

Before any later paid release, Sam should resolve permission for the Go quota endpoint and Grok CLI billing proxy, settle MiniMax's paid-display interpretation/hostname, and decide whether to replace Claude OAuth probing with the documented local status-line source. Provider names and trademarks should identify compatibility without suggesting affiliation; selling provider accounts, pooling credentials, or bypassing quotas is outside the assessed design. Re-read live terms at that time because this dated assessment is not a permanent clearance.
