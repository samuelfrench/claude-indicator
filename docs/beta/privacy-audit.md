# Beta privacy audit

Reviewed 2026-10-07 CT (2026-10-08 UTC). Baseline: `d857694a050ddfb8774ce99be64e774ded5d9426`. Scope: tracked product code, helper scripts, docs, image, tests, commit metadata, and all objects reachable from fetched local/origin refs. This is a source/data-flow audit and a bounded secret screen, not a claim that previously exposed data was never copied or that an exhaustive forensic investigation occurred.

## Verdict and exact headline

“Runs entirely on your machine, never sends your tokens anywhere” is **not literally accurate**. The desktop app runs locally, but sends bearer credentials to provider HTTPS endpoints, sends a Claude refresh token in an OAuth request body, delegates authenticated remote calls to installed Codex and GitHub CLIs, and can open a local page in the user's browser. No Indicator-owned backend, telemetry, analytics SDK, remote crash collector, ad SDK, or upload of task text/saved terminal history was found in the audited code. Provider and delegated-CLI processing remains governed by those services and the user's configuration; absence of Indicator telemetry does not establish absence of Codex CLI telemetry.

Proposed exact headline: **“Local desktop monitoring with no Indicator telemetry. Credentials go to their providers; the Indicator does not upload your task text or saved terminal history.”**

Detailed qualification: authenticated usage/auth requests leave the computer; GitHub receives discovered repository identifiers and runner queries. System proxies, TLS trust configuration, `GH_HOST`, delegated CLI configuration, clipboard managers and the browser are outside the Indicator's privacy guarantee. The existing Claude fallback is a real one-output-token inference request with the fixed text `quota`, consumes subscription usage and can incur extra usage according to account settings. It is not a passive read. No real provider requests were made for this audit's tests.

CLI subprocesses inherit the process environment; their own behavior must be assessed separately.

## Local reads, writes and exposure

| Local data | Flow and persistence |
| --- | --- |
| Claude credentials/settings/stats | Access/refresh tokens are read, used for the endpoints above, and not intentionally logged. `settings.json` fast-mode flag and `stats-cache.json` output/cache totals are displayed. The Claude session credential reader uses ordinary file open; unlike protected fallback/OpenCode/Grok readers it does not enforce mode 0600 or reject symlinks. Credentials remain under the user's control. |
| Codex sessions/state | JSONL files are read into memory to extract fresh `token_count` rate-limit events; nearby session text can therefore be in memory. SQLite is opened read-only; thread title, cwd, model and token totals are selected and visible in tooltips/expanded UI. The cache path is `~/.codex`, while installed CLI behavior also depends on its environment. No session content is uploaded by Indicator. |
| OpenCode ledger/auth | Read-only SQLite queries select numeric costs/token totals, model/provider identifiers and timestamps from message metadata, not prompt content. The auth JSON is read locally; unrelated provider entries can be in memory but only the selected key/token is used. Env credentials take priority. Protected credential files must be owner-controlled non-symlink mode-0600 regular files. |
| Claude usage state | `usage_history.json`, `last_usage.json`, rate-limit state and `widget.log` under `~/.claude` store quota/meters/reset/error/time data, not credentials or prompts. Legacy writers use ordinary files/atomic replacements and inherited umask; they do not uniformly guarantee 0600. A multiuser host should keep `~/.claude` private. |
| DeepSeek balance history | Local timestamped currency balances, 8-day retention, mode-0600 atomic/fsync persistence. Financial usage data can be visible on screen; avoid sharing real-account screenshots. |
| Terminal selector/recovery | Selector reads OS-accessible proc metadata, cwd, CPU/I/O activity and titles without an explicit UID filter; per-file OS permissions limit visibility. notes/park state persist under `~/.claude/terminal_sessions.json` (legacy inherited umask). Recovery reads names/cwd/TTY/PID/boot/times, never argv/environment/scrollback, and keeps durable records indefinitely in mode-0600 SQLite under mode-0700 `~/.local/state/claude-indicator`. A separate deploy-project scanner reads OS-accessible `/proc/<pid>/cmdline` for Claude detection, also without an explicit UID filter: the no-argv and current-user-only statements apply to recovery, not the entire app. Exact terminal selection may write temporary title-control sequences and use local xdotool/D-Bus; it does not send shell commands. |
| Smart TODOs | Reads `~/TODO.md` and bounded local workspace TODOs; task text/source/path/dates/rank remain local. Add/complete writes only the marked inbox in exact home TODO. Dismiss/pin/snooze/content-free scan observations use local atomic JSON. Source-opening launches editor/xdg-open with arguments, not shell text. “Copy context” and recovery copies use desktop clipboard; a separately configured clipboard-sync tool can transmit copied text. Source-open may hand content to a user-configured editor. |
| Host/project activity | `/proc`, `/sys`, mount counters, nvidia-smi, crontab/journal, local runner configs, git timestamps and optional task-loop project config supply system/cron/workflow status. Cron commands may contain private arguments and are visible locally. Task-loop reads are local configuration only: no AWS/DynamoDB SDK/calls remain in runtime. |
| Other local state | `widget_visibility.json` stores section/provider preferences; `smart_todos_finished.json` stores dismissed task identities, and `smart_todos_workflow.json` stores pin/snooze/content-free observations (atomic private temp files, preserving existing modes). The separate watchdog stores failure timestamps in `OLLAMA_WATCHDOG_STATE` or `/run/ollama-watchdog.state`; installed user units may override it. |
| Lifecycle | Singleton lock and systemd heartbeat are local. Installer writes optional unit/autostart only when separately invoked; install smoke must not invoke it. Faulthandler can write thread stacks/source paths to local stderr/journal; no remote crash collector. |

No claim of encrypted-at-rest state or uniform local permissions is made. Other users with access to the account, backups, screenshots, copied issue logs, clipboard sync and configured editors remain outside this threat model. These are bounded qualifications, not evidence of compromise.

## Public repository and history review

Baseline history screen after `git fetch origin`: **12 local refs, 150 reachable commits, 359 unique blobs, 19,912,070 blob bytes**. Pattern screen checked provider/GitHub/AWS credential prefixes, JWT shapes, private-key markers, quoted credential assignments and sensitive filenames. A second screen of nonhex strings at least 40 characters with Shannon entropy at least 4.45 found one candidate, manually classified as a historical library-path assignment, not a credential. It found **0 credential-pattern matches and 0 tracked credential/state filenames**, plus **640 personal-host-path matches and 225 email-shaped matches across file versions**. Counts refer to matches across unique blobs, not unique people or current files. Manual review distinguished template syntax/fixtures from personal context. Commit author/committer metadata contains a personal email; two noreply email variants also exist. A private redacted receipt is `~/indicator-beta/history-screen.json` (locations and digests only, no secret values).

Concrete public-data concerns at baseline:

- Product TODO includes personal operational logs, host paths, timings, usage/account figures and unrelated Route 53 tasks. Deployment notes and Smart TODO plans contain absolute owner paths. An email address is embedded in the original TODO.
- `docs/superpowers/{plans,specs}/2026-07-13-aws-cost-savings*.md` contains unrelated infrastructure topology/operational details and account-identifier-like numbers; this belongs in private operations context.
- Hardcoded task-group defaults refer to a specific personal project/outreach directory; reusable configuration should not publish a private workflow default.
- `docs/images/unified-indicator.png` visibly contains quota, token, spend and balance values. No credential, email, path or terminal/task text is visible in the inspected image, but its provenance as synthetic data was not established; remove it from current product docs to avoid repeating possible personal financial/usage data.
- `smart_todos.py`, `smart_todo_workflow.py`, `terminal_recovery.py` and their tests are reusable local functionality, not exports of Sam's actual TODOs, terminal DB, notes or CLI credential files. Keep the code; generalize identifiable documentation and fixtures. The named modules alone are not evidence of a leak.

Current-tree cleanup has been implemented: the unrelated AWS plans, workflow report and real-data screenshot were removed; owner paths/emails and personal operations narratives were generalized; task-group defaults are empty, and reusable TODO/recovery functionality remains. Before removal, 30 files were preserved in a private owner-controlled backup under `~/indicator-beta/repo-private-backup/`. A current-tree screen found 0 owner-path matches, 0 personal-email matches, 0 private-project-default matches, and 0 12-digit account-number-like matches. Independent source review confirmed the network inventory and corrected the distinction between OS-accessible process scans and owner-filtered recovery. Installation/full-gate/commit evidence is recorded separately in [install validation](install-validation.md) and the beta task file. Forward-only cleanup cannot remove copies, old commit blobs, author metadata, caches or forks. No history rewrite, force-push, credential rotation, repo deletion or repo split was performed.
